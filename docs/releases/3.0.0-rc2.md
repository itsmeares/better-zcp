# v3.0.0-rc2

This candidate updates the panel interface and replaces the external world-map
provider with map data from the installed game. It supports Project Zomboid
Build 42, one administrator, and multiple server profiles on Windows, Linux
or Docker.

## Changes from RC1

- Redesigned panel pages, navigation, forms and dialogs, with consistent light
  and dark themes and layouts for desktop and phone screens.
- The world map reads vanilla and Workshop map files from the selected server's
  installation. It no longer depends on pzmap.org. Floors, basements, search
  and zombie density use the local map data. Container search has been removed.
- Map diagnostics report local map and save information.
- GitHub release titles use the version tag alone, without a "Release" prefix.

## Install this candidate

Download the Windows ZIP or Linux tarball from
[v3.0.0-rc2](https://github.com/itsmeares/better-zcp/releases/tag/v3.0.0-rc2).
Verify it against the release's `checksums.txt`, extract the complete archive,
and run `Start.bat` or `start.sh`.

On an amd64 Linux Docker host, install the managed stack with:

```sh
curl -fsSL https://raw.githubusercontent.com/itsmeares/better-zcp/v3.0.0-rc2/infra/docker/all-in-one/bootstrap.sh | sh -s -- 3.0.0-rc2
```

The managed stack uses `ghcr.io/itsmeares/better-zcp:aio-3.0.0-rc2`.
For panel-only Docker, download this release's `docker-compose.install.yml`,
set its `image:` to `ghcr.io/itsmeares/better-zcp:3.0.0-rc2`, and follow the
[Docker guide](../install/docker.md) for game-folder mounts.
RC images do not update the `latest` tag.

## Existing installations

Back up the panel folder and game data before testing. For an existing 3.0 RC,
use the native panel updater. For a manual upgrade, stop the panel before
extracting and keep the entire `data/` folder, including secrets and backups.
Docker updates run from the host. A pinned panel-only Compose image tag must be
changed before pulling and recreating the service; see
[issue #120](https://github.com/itsmeares/better-zcp/issues/120).

For older installations, install into a separate folder, create the administrator
account, and register the existing server paths. Older `db.json` and `db.sqlite`
panel databases are neither imported nor deleted. Keep game saves, player
databases and configuration files, and stop the old panel before the new one
manages the same game servers. Do not run two panels against the same servers.
For an older combined Docker installation, save and stop the game before moving
to separate containers. See the [RC1 migration notes](3.0.0-rc1.md#existing-installations).

## RC checks still needed

- Local maps on real Build 42 installations, including Workshop map ordering,
  floors, basements, search and player positions.
- Connected Build 42 clients for player tools, using disposable characters
  when testing destructive actions.
- Real Steam/Workshop updates and maintenance with connected players.
- Windows game startup and Argus against an actual game server.
- Migration from an older combined Docker installation using copied game data.
- Two server profiles for selection, RCON, configuration, backup/restore and
  restart. Panel restart/update should preserve running games and login sessions.

Automated package startup, authentication and update checks do not replace these
gameplay checks. Report failures with the panel version, Build 42 version,
installation type and a support bundle with secrets removed.
