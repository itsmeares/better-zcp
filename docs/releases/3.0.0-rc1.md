# 3.0.0-rc1

This is the first release candidate of the rebuilt panel. It supports Project
Zomboid Build 42, one administrator, and multiple server profiles on native
Windows/Linux or Docker. Further candidates will use `3.0.0-rc2`, `rc3`, and so
on before the stable `3.0.0` release.

## Changes from 2.0.0-rc5

- Each server profile owns its connections, processes, settings, schedules and
  history. Selecting a server in one browser tab does not change another tab.
- A new SQLite database replaces the old panel storage. The panel has one
  administrator; roles, multiple users and OIDC login have been removed.
- Maintenance checks player activity and verifies saves before proceeding.
  Full backups stop the game; restore keeps a safety backup and can roll back
  a failed restore. Workshop updates are applied by PZ during a managed restart.
- Native panel updates verify packages, back up panel data and roll back after
  a failed health check. Panel updates leave running game servers online.
  Docker updates run from the host; the managed stack uses separate panel and
  game containers.
- Player tools include moderation, whitelist, access levels, teleport, item
  delivery, XP, invisibility, noclip, god mode, heal and kill. Argus supplies
  live character details, positions, heal/kill, item catalogue and live settings.
- The map reads provider metadata at runtime and reports unsupported mod maps.
  Diagnostics include provider status and a support bundle with secret masking.
- Authentication, streamed config scans, file access and update handling have
  stronger validation. Launchers preserve passwords and data paths, including
  spaces, Unicode and shell metacharacters.

## Existing installations

Back up the panel folder and game data before testing. Install the RC in a
separate folder, create its administrator account, and register existing servers
using their installation and Zomboid data paths. Stop the old panel before the
new panel manages the same game servers.

Older `db.json` and `db.sqlite` panel databases are neither imported nor deleted.
Legacy database import is not planned. Game saves, player databases and config
files remain in their original locations. Do not overwrite them with an empty
installation or run two panels against the same servers.

For an older combined Docker installation, save and stop the game before the
first migration to separate containers. Named volumes are preserved. Old panel
profiles still need to be registered again if they used the legacy database.

## Install this candidate

Download the Windows ZIP or Linux tarball from
[v3.0.0-rc1](https://github.com/itsmeares/better-zcp/releases/tag/v3.0.0-rc1).
Verify the archive against the release's `checksums.txt`, extract it, and run
`Start.bat` or `start.sh`. Use the complete archive, which includes the launcher,
matching web interface, game integration and installation guides.

On an amd64 Linux Docker host, the managed stack installer selects this exact
candidate with:

```sh
curl -fsSL https://raw.githubusercontent.com/itsmeares/better-zcp/v3.0.0-rc1/infra/docker/all-in-one/bootstrap.sh | sh -s -- 3.0.0-rc1
```

For a panel-only Docker deployment, download `docker-compose.install.yml` from
this release, change its `image:` to
`ghcr.io/itsmeares/better-zcp:3.0.0-rc1`, and follow the
[Docker guide](../install/docker.md) for the required game-folder mounts.
The managed stack uses `ghcr.io/itsmeares/better-zcp:aio-3.0.0-rc1`.

RC images do not update the `latest` Docker tag. `main` is the development image;
`latest` is updated only by stable release tags. To test another RC in a
panel-only deployment, change the Compose image tag before pulling and
recreating the panel service. The managed stack's versioned host command selects
the candidate directly.

For pinned panel-only images, the update command shown in Settings does not
change that tag for you. Edit it first; this is tracked in
[issue #120](https://github.com/itsmeares/better-zcp/issues/120).

## Known limits and RC checks

Map images load directly from PZMap's tile provider. Real metadata requests from
the G11 host currently return Cloudflare HTTP 403. A working metadata fixture
does not prove provider access; test the map from your deployment and check
**Debug > World Map**. The map is not considered verified until that succeeds.

Before promoting this candidate to stable, check:

- Connected Build 42 clients: heal/kill, god mode/noclip, XP, invisibility,
  teleport and live positions. Test destructive tools with disposable characters.
- Real Steam/Workshop content updates, including maintenance while players are
  connected. An empty Workshop scan is not an update test.
- Windows PZ startup and the game integration with an actual game server.
  Windows panel/launcher/update checks cover a different path.
- Migration from an older combined Docker container using copied game data.
  Check game/config data and the new separate-container lifecycle.
- Two server profiles: selection, RCON, configuration, backup/restore and restart
  must target the intended profile. A panel restart/update must preserve running
  games and existing login sessions.

Native package startup, authentication persistence, update success and health
rollback are automated checks. Their results do not replace the gameplay and
provider checks above. Report failures with the exact panel version, Build 42
version, installation type and a support bundle with secrets removed.
