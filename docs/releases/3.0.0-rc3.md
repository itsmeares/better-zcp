# v3.0.0-rc3

This candidate replaces the Docker setup. The panel itself is unchanged from
rc2. It supports Project Zomboid Build 42, one administrator, and multiple
server profiles on Windows, Linux or Docker.

## Breaking for Docker managed stacks

If you run the managed stack from rc1 or rc2, this update is manual. The stack
uses new compose files and new volume names (`ctx_*` becomes `better-zcp_*`),
and the `bootstrap.sh` installer and its `aio-` images are gone. Your data stays
in the old volumes until you copy it with `docker/migrate-rc-volumes.sh`, which
never changes or removes them. Follow
[Moving from the 3.0.0-rc1 or rc2 managed stack](../install/docker.md#moving-from-the-300-rc1-or-rc2-managed-stack).
Back up first. An untouched rc1 or rc2 stack keeps running on its existing images.

Native Windows and Linux installs and panel-only Docker installs are not
affected, apart from the image tag.

## Changes from rc2

- One image, `ghcr.io/itsmeares/better-zcp`, serves both the managed stack and
  the panel-only setup. It is 888 MB, down from 1.22 GB for the old managed image.
  The managed stack installs Project Zomboid with steamcmd on first start and
  retries the install up to three times (#124).
- `docker-compose.yml` is the managed stack and `docker-compose.panel-only.yml`
  is the panel for an existing Project Zomboid install. Install and update are
  plain `docker compose`. `docker-compose.install.yml` and the installer script
  are removed, and `CORS_ORIGINS` is optional.
- Tags are `X.Y.Z`, `latest` (newest release, release candidates included) and
  `stable` (newest release without a prerelease suffix, from 3.0.0 on). Images
  are published only from a release tag, after the release build and version
  check. The old `latest`, an unreleased snapshot, now points at rc2.
- Settings shows `docker compose up -d --pull always --no-deps panel` for a Docker
  update, and tells you to change `BETTER_ZCP_VERSION` when your compose file pins
  a version (#120).
- The Unraid template and the unused service templates are removed. Unraid users
  can run the panel-only image with their own container settings.

## Install this candidate

Download the Windows ZIP or Linux tarball from
[v3.0.0-rc3](https://github.com/itsmeares/better-zcp/releases/tag/v3.0.0-rc3).
Verify it against the release's `checksums.txt`, extract the complete archive,
and run `Start.bat` or `start.sh`.

On an amd64 Linux Docker host, install the managed stack with:

```sh
mkdir -p ~/zomboid-panel && cd ~/zomboid-panel
curl -O https://raw.githubusercontent.com/itsmeares/better-zcp/v3.0.0-rc3/docker-compose.yml
BETTER_ZCP_VERSION=3.0.0-rc3 docker compose up -d
```

For panel-only Docker, use `docker-compose.panel-only.yml` from the same release
and follow the [Docker guide](../install/docker.md#path-b-panel-only). Put
`BETTER_ZCP_VERSION=3.0.0-rc3` in `.env` to stay on this candidate; without it
the compose files follow `latest`.

## Existing installations

Back up the panel folder and game data before testing. For an existing native 3.0
RC, use the panel updater. For a manual upgrade, stop the panel before extracting
and keep the entire `data/` folder, including secrets and backups. Docker updates
run from the host. For the managed stack from rc1 or rc2, see the breaking section
above.

For older installations, install into a separate folder, create the administrator
account, and register the existing server paths. Older `db.json` and `db.sqlite`
panel databases are neither imported nor deleted. Keep game saves, player
databases and configuration files, and stop the old panel before the new one
manages the same game servers. Do not run two panels against the same servers.
See the [RC1 migration notes](3.0.0-rc1.md#existing-installations).

## RC checks still needed

- The first real tag publish of the image, including `latest` moving to this release.
- Managed stack first start on other hosts, and moving a copy of a real rc1 or rc2
  stack with its saves.
- The arm64 panel-only image on real hardware.
- Local maps on real Build 42 installations, including Workshop map ordering,
  floors, basements, search and player positions.
- Connected Build 42 clients for player tools, using disposable characters
  when testing destructive actions.
- Real Steam/Workshop updates and maintenance with connected players.
- Windows game startup and Argus against an actual game server.
- Two server profiles for selection, RCON, configuration, backup/restore and
  restart. Panel restart/update should preserve running games and login sessions.

Automated package startup, authentication and update checks do not replace these
gameplay checks. Report failures with the panel version, Build 42 version,
installation type and a support bundle with secrets removed.
